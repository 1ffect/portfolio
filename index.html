项目要回答什么

AI 主机作为独立硬件，如何区别于 PC、手机、云端 Agent 与自部署工具？我围绕办公任务、本地资源调用、跨端协同、智能终端联动与长任务执行，参与梳理目标用户、核心任务和首版能力范围。

我负责的核心部分

AI 主机 Agent 是产品核心价值之一。我主要负责 Agent 产品方案，并作为记忆机制 0→1 前期方案 Owner，定义记忆与上下文、聊天记录和业务事实的边界。

15 个方案如何变成产品判断

通过市场调研、文档调研与源码分析，我比较 15 个开源记忆方案的产品定位、能力链路、技术依赖和场景适用性，围绕写入、组织、检索调用、更新与失效、用户可控和隐私边界形成方案，初步选定 Hindsight 为重点参考。

不只设计“记住”

我同时研究 AI OS、AUI 与端云协同，围绕任务进度、权限授权、关键节点确认、异常回退、人工接管、执行日志和结果追溯设计交互原则。

企业 AI 提效项目 · AI 产品经理实习

新人学习与问答平台

从“做一个提效工具”的模糊目标出发，我找到新人培训场景，并把结构化学习、产品知识检索和即时问答收敛成可交付、可测试的 MVP。

45天→14天

6 名新人灰度样本中的上手周期变化

先确定谁真的需要帮助

我访谈 10 名新人和 4 名带教，把宽泛的“提效”收敛为三类任务：按顺序学习、快速找到产品资料，以及在遇到问题时及时得到回答。

把分散资料变成知识结构

我覆盖 3 条产品线和 10 个以上型号，按四层学习路径重组资料，拆解 40 多个知识点和 100 多个 FAQ，并建立 ID、标签和 URL 映射。

学习平台与 Agent 协同

我使用 HTML 与 JavaScript 完成平台前端，在办公协作平台搭建知识库 Agent，配置分层检索与 Prompt，并输出知识结构、功能说明、产品流程与问答 SOP。

回答失败也要留下信息

问题被分为“可独立回答”“需人工补充”和“知识库缺失”。缺失问题、不稳定回答和新增 FAQ 会重新回流知识库与 Prompt，形成可以持续迭代的闭环。

小样本验证

项目先进行 3 人内部测试，再由 6 名新人灰度试用。6 人样本中，上手周期由约 45 天缩短到约 14 天，AI 问答覆盖率超过 60%；这一结果只用于验证 MVP 方向，不外推为全量业务效果。

个人开源情感陪伴 Agent

idol-skill

把公开物料与用户主观记忆蒸馏成高光时期的陪伴人格，并允许用户通过反馈持续纠正它，而不是只生成一次固定人设。

Agent SkillPython CLI分层记忆Local-first

从材料到可确认的记忆

流程包含材料导入、清洗与标签化、用户预览确认、索引构建和记忆检索。原始材料不会未经确认就直接污染角色记忆。

角色一致性不是一段 Prompt

我设计核心、情感、动态、增强和纠偏等记忆层，并建立四类 Persona Matrix、情绪路由、说话节奏、安全规则与检索权重。

持续修正

当用户认为回答不符合角色时，反馈会进入 OOC 纠偏流程并回写修正规则。项目同时提供评测脚本、示例数据、无 API fallback 与 Skill 导出能力。

当前状态

项目已发布 v0.1.0，适合作为 Agent Skill、Python CLI 或交互原型使用；它不是已经商业化或拥有大规模活跃用户的线上产品。
